The block-ID model is useful, but navigation can lose its target. `takeScrollTargetSelector()` clears the target before EditableText knows that CKEditor has a DOM root, so content arriving before editor initialization can consume the link without scrolling. Advise clearing only after a target is found or retrying after editor readiness.

ReadOnlyText also reruns the scroll effect only when `blob` changes, so navigating to another block in the same open note does not retrigger it. Advise making the view-scope target part of the effect trigger. The revision side effect, toolbar placement, Markdown omission, and profiling need are already declared spike decisions.
