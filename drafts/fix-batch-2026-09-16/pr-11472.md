## Why

Closes #11472

On a short desktop window the note actions (three-dot) menu runs off the bottom of the window. The "Delete note" row is cut off, and the "Advanced" submenu is clipped, so "Note source" cannot be reached. There are two causes.

1. `<Dropdown className="note-actions">` in `NoteActions.tsx` passed no `popperConfig`. Popper's `preventOverflow` then guards only the main axis, which is x for a bottom placement. The menu is about 617px tall. With room neither below nor above the toggle, it kept its bottom placement and hung off the window. `IconPicker.tsx` already had an inline `altAxis` guard for the same fault.
2. `FormDropdownSubmenu` in `FormList.tsx` always opened downward (`top: 0`). The logic that adds `submenu-flip-up` and `submenu-flip-start` was the private method `ContextMenu.repositionSubmenu`, so only jQuery context menus used it.

## What

- `repositionSubmenu` moved from `context_menu.ts` to the new `menus/submenu_placement.ts` as an exported function. The logic is unchanged; its constant is now `VIEWPORT_PADDING`. It has its own module because `context_menu_utils.ts` builds menu items and pulls in i18n.
- `FormDropdownSubmenu` holds a ref to its `<ul>` and calls `repositionSubmenu` on `mouseenter`, on desktop only. The mobile layout unfolds submenus in place.
- The icon picker's inline guard is now `keepMenuInViewport(defaults)` in `Dropdown.tsx`. `IconPicker.tsx` and `NoteActions.tsx` pass it as `dropdownOptions.popperConfig`. `NoteActions.tsx` passes it on the desktop layout only.
- Two CSS comments in `style.css` now name `repositionSubmenu()`.

## Scope

- A desktop window shorter than the menu still cannot show all of it. At 600px high the menu is now -25..592: the last rows are on screen and the first row is cut, where before the last rows were cut. The menu cannot scroll, because submenus are absolutely positioned children (`style.css`: "Cannot set overflow: auto, submenus will break"). The icon picker already behaves this way.
- Issue 11106 (tablet mode) has a different cause: the mobile sheet rules are inside `@media (max-width: 991px)`. It is not changed here.
- `submenu-flip-start` has no effect on a `dropStart` submenu, because both use the same CSS declarations. All submenus in the note actions menu are `dropStart`, so only the vertical flip applies to them. This limit existed before.
- I did not check a right-to-left locale live. Unit tests cover the sideways flip.
- `NoteActions.tsx` has no spec, so no test covers its one-line `dropdownOptions` prop.
