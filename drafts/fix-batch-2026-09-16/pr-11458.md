## Why

Closes #11458

A bookmark in the launch bar opened in a new tab lands at the end of the tab row, not next to the current tab. This happens for Ctrl-click, middle-click, and "Open note in a new tab" in the right-click menu. Entries inside a bookmark folder already open next to the current tab, as the reporter saw.

Root cause: tab placement is an opt-in argument that defaults to `"end"` (`TabManager.openEmptyTab()`, `openContextWithNote()`). #10151 (commit 64fef95f19) passed `"afterCurrent"` from `link.ts`, `note_tree.ts` and `tree_context_menu.ts`, but two user-driven paths were not wired:

- `launchCustomNoteLauncher()` in `GenericButtons.tsx` calls `TabManager.openInNewTab()`, which had no placement parameter and always appended. This is the Ctrl-click and middle-click path for bookmarks and all other note launchers.
- `handleLinkContextMenuItem()` in `link_context_menu.ts` called `openContextWithNote()` without `placement`. This is the "Open note in a new tab" menu item.

Bookmark-folder entries are `NoteLink`s handled by `link.ts`, which already passes `"afterCurrent"`.

## What

- `tab_manager.ts`: `openInNewTab()` gets a 4th optional parameter `placement: TabPlacement = "end"` and passes it to `openEmptyTab()`. The default keeps the programmatic callers (options dialog, popup editor, sidebar chat, right panel, help call-to-action) appending.
- `GenericButtons.tsx`: `launchCustomNoteLauncher()` passes `"afterCurrent"`.
- `link_context_menu.ts`: `handleLinkContextMenuItem()` passes `placement: "afterCurrent"`.
- Tests: a new placement case in `tab_manager.spec.ts`, a new `GenericButtons.spec.tsx` for `launchCustomNoteLauncher()`, and three updated expectations in `link_context_menu.spec.ts`.

Behavior change to note: `handleLinkContextMenuItem()` is shared by all link context menus (text links, breadcrumb, note map, board, calendar, table, dashboard, geomap, relation map, embedded note pane), not only bookmarks. All of them now open the tab after the active tab. This agrees with the commit text of #10151, which put the "open in new tab" context menu in scope but wired only the tree menu.
