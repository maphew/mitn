## Why

With "Enable transitions and animations" on, press Ctrl+L (add link) or Ctrl+J (jump to note) in a text note and type at once. The typed characters go into the note, not into the dialog.

Root cause: `openDialog()` in `apps/client/src/services/dialog.ts` saves the focused element but leaves it focused. Bootstrap 5.3.8 moves focus only when its focus trap activates, which is after the backdrop fade (.15s) and then the modal fade (.3s). For about 450 ms `document.activeElement` is still the CKEditor editable. With animations off there is no such window, which agrees with the workaround in the issue thread.

Closes #7996

## What

`openDialog()` now moves focus to the dialog's own backdrop immediately after `Modal.show()`. The element that had focus is saved first, so the focus restore on close does not change. Bootstrap moves focus into the dialog when the transition ends, as before.

Focus goes to the backdrop and not to nothing, because `AttributeEditorOverlay` reads `focusout.relatedTarget` (`.modal, .modal-backdrop`) to keep the sidebar attribute editor open while the note type chooser opens. A plain `blur()` gives a null `relatedTarget` and that editor would commit and unmount.

The move is skipped when the dialog is opened with `focus: false` (PopupEditor) and when focus is already inside the dialog. A dialog with `backdrop: false` gets a plain `blur()`.

Result: keys typed during the opening transition are dropped. The reporter named this as an acceptable result.

## Scope

- Type-ahead into the dialog input (the result the reporter preferred) is not included. It needs the modal displayed before the backdrop fade ends, and changes to each dialog's `onShown` (`showRecentNotes` clears the value, `.trigger("select")` selects the typed text).
- Focus moves about 10 to 25 ms after the shortcut, and about 50 ms on the first open of a dialog in a session (`LazyDialog` dynamic import, measured on the dev server). A key pressed inside that time still goes to the editor. I did not measure a production build.
- The backdrop gets `tabindex="-1"` and `outline: none` so that it can hold focus without a visible ring. It is not in the tab order.
