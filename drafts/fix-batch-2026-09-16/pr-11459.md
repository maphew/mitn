## Why

When a reference link reaches the end of a line, the note icon can stay alone on that line while the title moves to the next line. This occurs in the editor, in read-only text and on share pages.

Root cause: `loadReferenceLinkTitle()` (`apps/client/src/services/link.ts`) and `cleanUpReferenceLinks()` (`apps/server/src/share/content_renderer.ts`) put a bare `<span class="tn-icon bx ...">` before the title text. The generated icon-pack rule (`packages/trilium-core/src/services/icon_packs.ts`) sets `display: inline-block` on that span. CSS permits a soft wrap on each side of an atomic inline, and no rule keeps the icon with the first word of the title.

Closes #11459

## What

- `.reference-link .tn-icon` (`style.css`) and `a.reference-link > span > .tn-icon` (share theme `content.css`) get `display: inline; white-space: nowrap`. `::after { content: "\2060" }` adds a word joiner, so no break opportunity stays between the icon and the first title character. `::before { display: inline-block }` keeps the link underline off the glyph, as before.
- `getLinkIcon()` now returns `tn-icon bx bx-code-curly` and `tn-icon bx bx-file` for the `source` and `attachments` view modes. These two icons had no `tn-icon` class, so the reference-link rules (the new ones and the existing 3px gap) did not match them. The share renderer already adds the class.
- The DOM shape, `$el.text()` and the clipboard text do not change.

The fix proposed in the issue (a U+00A0 or U+2060 text node next to the icon) does not prevent the break in Chromium. The break stops only when the icon and the word joiner are in one `white-space: nowrap` inline box.

## Scope

- Trade-off: with `display: inline` on the icon span, helpers that need a box do not apply to an icon in a reference link. These are the boxicons transform and animation classes (`bx-rotate-*`, `bx-flip-*`, `bx-spin`, `bx-tada`, `bx-burst`, `bx-flashing`, `bx-fade-*`) and the fixed width of `bx-fw`. The icon picker does not produce them. Only a hand-written `#iconClass` can. If this is not acceptable, the alternative is a `<span class="reference-link-icon">` wrapper with `white-space: nowrap` and the word joiner, which changes `link.ts`, `content_renderer.ts` and their specs.
- Not changed: the bookmark and board-column icons in the `<small>` part of a reference link. They have the same shape and can wrap the same way. I left them for a separate change.
- Not fixed: a title that starts with a space (the break after the space stays), and editor paragraphs narrower than about 60px, where `overflow-wrap: break-word` in `.ck-content` permits an emergency break.
- No layout test is added, because happy-dom has no layout. A Playwright assertion in `apps/server/e2e/shared_notes.spec.ts` is possible if a maintainer wants one.
- Not verified: Firefox and Safari. `white-space: nowrap` and the word joiner (UAX14 rule LB11) are standard, so the worst case I expect is that the underline shows below the glyph. Only the default theme was driven in the live check.
