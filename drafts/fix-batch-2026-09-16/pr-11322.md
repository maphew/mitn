## Why

Closes #11322

A mermaid note can log "Failed to execute 'inverse' on 'SVGMatrix': The matrix is not invertible", and after that the pan/zoom controls of the preview do not come back. The reported stack (`zoomAtPoint <- zoom <- publicZoom <- effect`) maps to one line: `zoomInstance.zoom(lastPanZoom.current.zoom)` in `useResizer` (`apps/client/src/widgets/type_widgets/helpers/SvgSplitEditor.tsx`).

Root cause: the pan/zoom setup effect in `useResizer` starts svg-pan-zoom on any SVG it finds. svg-pan-zoom 3.6.2 measures the SVG on init and fits the scale as `min(width / viewBox.width, height / viewBox.height)`. A box with zero width or height gives a scale of 0, and a `viewBox` without an area gives NaN or Infinity. The first `zoom()` then calls `getCTM().inverse()` and throws. The throw happens before `zoomRef.current` is set, so each later svg or width change throws again.

The only guard was `width?.width === 0` from `useElementSize`. It does not check the height, the SVG itself or the `viewBox`. It also passes while `width` is `undefined`, which is permanent when the preview pane mounts lazily, because `useElementSize` then attaches no ResizeObserver.

## What

- `useResizer` returns before `svgPanZoom(...)` when the new helper `canFitSvg()` says no. One source file, 16 added lines.
- `canFitSvg()` needs a bounding box with a positive width and height. If a `viewBox` is present, it parses it the way svg-pan-zoom does and needs a finite, positive width and height.
- The early return registers no cleanup and leaves `zoomRef` unset, so the next svg or width change tries again.
- No try/catch, no change to `useElementSize`, no new dependency.

## Scope

- `canFitSvg()` reads `getBoundingClientRect()` only. svg-pan-zoom prefers `clientWidth`/`clientHeight` when both are non-zero. A mismatch can only make the guard skip a diagram, not let a bad one through.
- An SVG without a `viewBox` is trusted. svg-pan-zoom then fits from `getBBox()`. Mermaid output has a `viewBox`, so I left that path as it is.
- When the preview pane mounts lazily, no ResizeObserver is attached, so pan/zoom comes back only on the next edit after the pane becomes visible. This is existing behaviour and not part of this change.
- Which of the boxless states the reporter hit is not known.
