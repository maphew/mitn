## Why

On Linux and Windows, Ctrl+M minimizes the Trilium window when the text editor does not have focus, for example in the note tree or in a non-text note.

Closes #9753

Trilium never calls `Menu.setApplicationMenu`, so Electron installs its default application menu. The main and extra windows call only `setMenuBarVisibility(false)` in `apps/desktop/src/services/window.ts`. That hides the menu bar, but the menu accelerators stay active. The default Window menu contains the `minimize` role, and Electron binds that role to `CommandOrControl+M`. Electron fires a menu accelerator only for a key that the renderer did not consume. In a text note, the CKEditor math plugin consumes Ctrl+M. In other places the key falls through to the hidden menu, and the window minimizes. Trilium's keyboard actions consume the other default accelerators, so Ctrl+M is the one that shows.

## What

- `setupWindowing()` now installs an application menu at `app.whenReady()`, through a new `setupApplicationMenu()` helper in `window.ts`.
- The menu is Electron's default template with the Window menu reduced to `close`: `fileMenu`, `editMenu`, `viewMenu`, and `{ role: "windowMenu", submenu: [{ role: "close" }] }`. All other default accelerators stay, for example Ctrl+Q on Linux and Ctrl+Shift+R.
- macOS is not changed. Cmd+M is the platform standard there, and the default Edit menu backs the clipboard shortcuts.
- The platform check reads `process.platform`, because the app can be ready before `initializeCore()` makes `coreUtils.isMac()` usable. For the same reason a failure goes to `console.error` and not to the log service.
- `whenReady()` is used so that `apps/edit-docs`, which calls `setupWindowing()` after `ready`, also gets the menu. The setup window keeps its own `removeMenu()`.

## Scope

- A custom `submenu` on the `windowMenu` role relies on how Electron's `MenuItem` resolves it: an explicit submenu wins over the role default. The unit test reads only the template, so it cannot detect a change in that Electron behavior. I kept the role and did not use `{ label: "Window" }`, because that would add an untranslated string.
- Alternatives that I did not choose: `Menu.setApplicationMenu(null)` is simpler but removes Ctrl+Q on Linux and the Ctrl+Shift+R fallback. `{ role: "minimize", registerAccelerator: false }` keeps the menu item but still shows a Ctrl+M that does nothing. With the chosen menu, users of a global menu (KDE, Unity) lose the Window > Minimize item.
- The menu labels are Electron's English role labels, as they were with the default menu. Translation of the menu is not part of this change.
- macOS is out of scope. There, CKEditor maps the math keystroke to Cmd+M and the native menu gets the key first, so the math shortcut does not work. That needs a different keystroke or a move into `keyboard_actions`, in a different PR.
- The menu must be set before the first window exists. `main.ts` and `apps/edit-docs` do this now, but no test makes sure that the order stays.
