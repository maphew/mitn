Reproduced with the Trilium Next theme in a dev client: the reference link counted as a result but stayed unhighlighted.

Cause: the theme rule `.use-tn-links a` sets `background: var(--background)` on every anchor. Its specificity beats CKEditor's `.ck-find-result` and `.ck-find-result_selected` rules, so the reference link widget, an `<a>`, lost the highlight. Mentions (`<span>`) and cards (`<section>`) were not affected.

Fix in the latest push: the plugin now ships `find_in_link_widgets.css`, which restates both find colors at widget specificity (`.ck-content .ck-widget.ck-find-result`). Verified in the running client that the reference link shows the yellow highlight and the orange current-result color, with a browser regression test that injects an equivalent theme rule.
