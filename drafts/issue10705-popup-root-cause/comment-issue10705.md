Triaged all six demos plus the follow-up comment against current main (372a749ff2), tracing each symptom to code. They are five separate bugs, not one. Suggest splitting into five issues and keeping this one as the tracker.

**1. Launch bar icons + Web Clipper badge (one bug).** Both tooltips are Bootstrap tooltips created by `useStaticTooltip` (`widgets/react/hooks.tsx:1135`, trigger `hover focus` in `widgets/react/ActionButton.tsx:52` and `widgets/react/Badge.tsx:32`). `ContextMenu.show()` only dismisses the note-preview tooltips (`menus/context_menu.ts:91` calls `note_tooltip.dismissAllTooltips()`), never these, and the hook's dismiss-on-press listens to `click` only (`hooks.tsx:1178`), so right-click leaves the tooltip standing over the menu. The old widget hid its tooltip on right-click (`widgets/buttons/abstract_button.ts:42`); the Preact port dropped that. Smallest fix: hide the static-tooltip set when a context menu opens, or add `contextmenu` to the dismiss-on-press listener.

**2. PDF note menus.** The PDF is pdf.js in a cross-document iframe (`file/PdfViewer.tsx:47`). Menu dismissal relies on parent-document click listeners (`menus/context_menu.ts:84`; Bootstrap dropdown autoclose likewise), and clicks inside the iframe never bubble out, so neither the right-click menu nor the three-dots menu closes. A click bridge already exists for tab activation (`file/Pdf.tsx:241`); dismissing floating layers there too would be the smallest fix.

**3. ETAPI context menu behind the dialog.** `#context-menu-container` is `z-index: 2000` (`stylesheets/style.css:1670`) and is created before the modal in the DOM; the prompt modal is also 2000 (`dialogs/prompt.tsx:50`, bumped by `services/dialog.ts:180` when modals stack). Tie goes to DOM order, so the modal paints over the menu. Reproduces in any prompt/confirm modal, not just ETAPI settings.

**4. Inline link popup + attributes panel (likely one bug).** Both stuck popups are CKEditor balloons portaled to `.ck-body` in the body: the LinkUI actions balloon (stays after tab switch) and the attribute editor's mention autocomplete (reanchors to the window origin after the panel closes, the signature of positioning against a hidden target). Nothing tears these down when their host is hidden; the only global cleanup is `$("body > div.tooltip").remove()` on tab close (`components/tab_manager.ts:538`), which does not match `.ck-balloon-panel`. This one is code-inferred rather than stepped through, so it may split further once someone debugs it.

**5. Menus taller than the viewport (from the follow-up comment).** `positionMenu()` clamps position but not height (`menus/context_menu.ts:140-186`), and `overflow: auto` is explicitly forbidden because submenus are DOM children (`stylesheets/style.css:1634`). Structural limitation, enhancement-shaped, unrelated to the four above.

Two fixes landed after this was filed and may already cover parts of it: df0cb94187 (note-preview tooltip vs context menu, 2026-07-28) and 5d99e3b02d (tooltip hidden on the press that opened something, 2026-08-01). All six demos predate both, so every surface still needs a repro attempt on a current nightly before splitting; my expectation from the code is that 1, 2, 3, and 5 still reproduce, item 4's tab-switch case likely does, and the attributes-panel case is the most likely to have changed given the attribute UI rework of late July.
